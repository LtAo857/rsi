# 逐机制消融工具验证

日期：2026-11-06。本批只有离线开发与测试，没有新增付费模型调用。

新增 ablate 命令，读取显式 name/path/before/after 规格。最多 5 个独立变体、每变体
1–5 个输入种子。每个变体从当前版本单独复制，仅允许现有 agent/ 源码，精确匹配一次并
缩短指定块。名称与路径检查、语法检查、健康检查在所有变体准备完成后才允许评分开始。
缩短源码不能证明关闭了某项语义机制；规格正确性仍由实验设计者负责。

每个 trial 独立执行基线与变体，交替执行顺序，使用相同输入种子，验证任务逐一对应。
记录得分、每题退步与改善、调用数和已报告 token。结果不写入搜索历史、不发布版本，
不自动决定删除。评测仅覆盖任务能力，不覆盖进化策略的修复能力，因此不允许修改 evolution/。

独立审计目录保存变体源码、逐次评测和增量报告。异常时记录失败状态并保留已完成数据；
用量通过原有账本与调用边界执行。只有完整成功的报告才更新 ablation.json。

新增示例分别删除分页提示与 schema 提示。真实模型的机制消融尚未执行，示例不代表这两项
提示无用，也不改变当前运行版本。没有判定通用冗余或获得持续能力增长。

新增测试首批 7 项通过，2.326 秒；补充机制退步测试后 8 项通过，4.945 秒。
测试覆盖精确匹配、路径和规格约束、所有变体提前检查、相同输入及顺序交替、版本与历史
保持不变、未知 token 不冒充零、CLI 报告，以及预算中断后保留账本和失败报告。

机制退步测试使用始终返回 fenced JSON 的离线适配器：保留解析机制时 DataDesk 5/5，
独立副本关闭 fenced JSON 解析后 0/5，报告记录 5 个退步任务。该反例用于证明工具能检测
被关闭机制的行为影响，不代表真实模型会始终生成此类响应。

全量阶段：首轮 110 项通过（80.770 秒）；补充反例后最终 111 项通过（74.116 秒）。
示例两个规格在当前种子源码均精确匹配，生成副本可编译；README 本地链接与
`git diff --check` 均通过。没有开展真实付费消融，没有改动活跃实验版本。
