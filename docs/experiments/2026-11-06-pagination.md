# 分页任务开发与验证

日期：2026-11-06。本批未发起付费模型调用。

此前真实提示消融以 SQL 路径为主，未触发多页结果，不能回答分页提醒是否有用。本批
新增独立锁定的 datadesk-size pagination 环境，仅开放 list_files、read_csv。read_csv
每页最多 20 条记录，SQL、schema、read_file 均不可用；常规 compact/full 工具保持原样。
这是明确的 CSV-only 任务环境，不是认为一般 SQL 数据分析必须用分页。

固定生成器每题产生 61–79 行 records.csv，任务为活跃记录计数、活跃记录数量求和。
数量均为正，最后一行为 active，确保后续页贡献非零，只读第一页不可能得到完整答案。
生成器及答案摘要保持在固定层，数据路径和答案摘要不进入任务模型提示词。

同一输入种子可重现数据，配对任务相同。留出使用 seed + 1000000007 生成新数据，
仍是同两类问题，不宣称跨任务类型泛化。环境配置持久化，不能在旧实验中切换。
缓存指纹包含新生成器；分页能力可沿用评测、诊断、消融、确认与用量控制。

新增 5 项测试全部通过，3.303 秒。覆盖生成器可重现、强制页大小和工具范围、路径与
参数限制、逐页读取与提前回答的差异、留出数据和配置锁定，以及 CLI 和消融闭环。

离线脚本读取 offsets 0、20、40、60 后提交答案，2/2 正确；仅读取第一页则 0/2，
诊断记录 unread_pages。以提示字符串控制模拟器是否续页时，移除提示的消融报告记录
2 个退步任务。这是预设模拟行为，只证明新任务能暴露分页能力缺口，不代表真实模型
一定受此提示影响。活跃版本与搜索历史未被消融修改。

提供 examples/ablation-pagination.json，仅关闭分页提醒，避免在 CSV-only 环境中
用 schema 提醒作为无关消融。后续真实实验仍需检查实际轨迹、准确率与重复试验稳定性。
